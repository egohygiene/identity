# ADR-0034: Publish verified native v1 artifacts through the existing release publisher

## Context

The native consumer-kit boundary already verifies generated public source and
optional projections. The legacy Identity publisher reconstructs brand facts
from publication configuration and packages the full older asset tree. Those
paths do not yet form the real self-source handoff required by #98.

The current publication configuration also requires its selected tag's own
commit inside release-owned bytes. A newly created commit cannot contain its
own hash. Preserve the exact v1.0.0 compatibility binding while defining an
explicit native release-owned selection without that circular requirement.

## Decision

Propose an opt-in `sourceMode: native-v1` configuration. The existing publisher
still resolves a published stable annotated tag and checks out its exact
commit. Native configuration declares `release.defaultTag` and
`release.binding: selected-annotated-tag`; the verified selection supplies the
commit. Require native configuration to come from that release tree. Keep
legacy exact tag/commit configurations and their compatibility index unchanged.

Reuse the existing native preparation/verifier boundary. Preserve native model
and compiler manifest bytes; compose only the already supported optional
views. Configuration owns routes and selected local generated-input paths,
not project facts, tokens, artwork, copy or approvals. Copy only the verified
native/projection inventory. Add publication metadata and retain Decisions
composition and independent organization-route ownership.

Preserve the legacy public manifest/site `sourceDigest` as the framed asset
inventory digest. Native mode additionally exposes `canonicalSourceDigest`
from the unchanged native source binding. Verify both independently; never
reinterpret one algorithm as the other or weaken compiler/download integrity.

## Alternatives considered and rejected

- Re-enter v1 facts in the legacy config: this would keep a competing source
  of brand truth and lose the actual native handoff.
- Replace old releases with native-generated bytes: immutable compatibility
  artifacts must retain their original source and meaning.
- Guess a release commit before creating it: a fabricated self-reference is
  not immutable release evidence.

## Consequences and tradeoffs

Native mode has additional release-owned-input and dual-digest checks. Existing
native packages remain asset packages; optional downloads retain their own
identity. Publisher changes still need later runtime and release qualification.
Source validity, artwork rights, published release, deployment and live/rollback
verification remain separate gates. No deployment policy changes here.

## Implementation and evidence links

The [owner packet](../work/98/OWNER_PACKET.md) inventories real source, missing
rights and exact future gates. The native adapter is an unqualified source
draft. No execution proof, ADR acceptance, release or deployment is supplied.

## Replacement or exit strategy

Omit native mode to retain the existing compatible legacy publisher. Roll back
publication through its existing immutable release/artifact owners. Never
rewrite historical receipts, replace a stable tag or silently substitute a
different source model. Organization /identity/ rollback stays independent.

## Follow-up work

Obtain actual owner facts, qualify native source/artifacts, verify the annotated
tag selection and malformed/mixed-input rejection, preserve legacy bytes and
Decisions composition, and exercise live rollback and real consumer adoption
in the later approved campaign. This proposal remains proposed.
