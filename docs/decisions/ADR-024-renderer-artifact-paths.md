# ADR-024: Separate bundle-relative artifact paths from deployment bases

## Context

ADR-010 defines the immutable renderer port; ADR-014/015 govern optional
projections and ADR-019 preserves published releases. The existing renderer
contract requires release-relative downloads, but generic URL construction
accepts traversal and strips leading slashes. Optional projections apply
different path checks, and imported Design System views inspect only the first
artifact. The precise normalization and compatibility rules need a durable
record beyond the repair itself.

## Decision

Propose one shared [renderer artifact-path contract](../contracts/BRAND_KIT_RENDERER_V1.md#artifact-paths-and-configured-deployment-bases).
Validate all core/optional download paths before rendering and again when
constructing a URL. Treat them as bundle-relative URL paths: normalize one
leading `./` and safe segment encoding; reject traversal, absolute paths,
schemes, backslashes, encoded separators and nested encoding. Keep all four
Design System filenames together and confine published Press Kit links to
their declared directory.

Keep explicit local/route/HTTP(S) deployment bases separate from model paths.
The existing publication `releaseUrl` remains an external navigation link;
there is no new generic external-download variant or model field. Rendering
does not fetch from the configured base.

## Alternatives considered and rejected

- Keep independent generic/optional checks: retains inconsistent validation and
  misses secondary imported artifacts.
- Strip rooted paths or let URL resolution normalize traversal: silently changes
  the declared download location and can leave a configured bundle prefix.
- Decode repeatedly or accept URL-shaped paths as external downloads: creates
  ambiguous interpretation without an explicit external-download contract.

## Consequences and tradeoffs

Current compiler package targets, offline rendering and configured route/CDN
bases remain usable. Imported paths starting with `/` now fail; consumers put
deployment prefixes in the explicit base instead. Colons, query/fragment
delimiters, malformed encoding and decoded percent signs are unsupported in
artifact filenames. Safe spaces/Unicode are serialized consistently. The
renderer validates without mutating models, generated bytes or release hashes.

## Implementation and evidence links

The candidate adds [the shared validator](../../renderer/src/artifact-paths.js),
core/optional import guards, static CLI regressions, and prefixed HTTP download
checks. Actual validation and immutable candidate evidence belong in the PR
and [continuity checkpoint](../../CONTINUITY.md). Implementation and merge do
not supply human disposition for this proposal.

## Replacement or exit strategy

Retain immutable historical renderer/tool selections and whole release sets
for rollback. Review newly supplied models/configuration against the path
contract rather than patching old published bytes. Any future external-download
variant needs an explicit versioned shape and compatibility tests.
