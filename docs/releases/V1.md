# Identity v1 release guide

`1.0.0` is the first stable Identity CLI release. It is independently
installable, reproducible, and fully gated. The final `v1.0.0-rc.2` prerelease
proved the same source-install, renderer, packaging, provenance, and GitHub
publication path before this stable promotion.

## Supported distribution

Identity intentionally does **not** publish to crates.io. The supported v1
distribution is a pinned source install from a GitHub release tag, plus a
Linux x86_64 GNU archive attached to that tag. This keeps the compiler,
contracts, renderer, and lockfile in one auditable release boundary.

### Locked source install (Linux, macOS, and Windows)

Install Rust `1.97.1`, then run:

```bash
cargo install --locked \
  --git "https://github.com/egohygiene/identity" \
  --tag "v1.0.0" \
  identity
identity --version
```

The repository's [toolchain file](../../rust-toolchain.toml) records the exact
compiler and components used by CI. `cargo install --locked` consumes the
committed dependency resolution rather than selecting new compatible versions.

### Prebuilt Linux archive

Download `identity-1.0.0-linux-x86_64-gnu.tar.gz` and `SHA256SUMS` from
the matching GitHub release. Verify the archive before extracting it:

```bash
sha256sum --check SHA256SUMS
tar --extract --gzip --file "identity-1.0.0-linux-x86_64-gnu.tar.gz"
./identity --version
```

Also inspect the attached SPDX SBOM, license inventory, and GitHub build
provenance attestation.
The archive targets Linux x86_64 with GNU libc; use the source-install route
for other platforms and libc variants.

## Quickstart: generate the complete example Brand Kit

The repository contains a reviewed, complete v1 example. Clone the immutable
release, copy the fixture to a consumer directory, and generate it:

```bash
git clone --depth "1" --branch "v1.0.0" \
  "https://github.com/egohygiene/identity" "identity-v1-example"
cp --recursive "identity-v1-example/tests/fixtures/v1/valid/minimal" "example-brand"
identity v1-generate --repository-root "example-brand"
identity v1-verify --repository-root "example-brand"
```

The generated Brand Kit appears under `example-brand/assets/identity/`. It
contains selected package profiles, a compiler manifest, checksums, and the
reference-renderer view model. `v1-verify` is read-only and fails if the output
is missing, stale, or drifted.

For the canonical source topology, schemas, diagnostics, and migration rules,
read the [v1 identity contract](../contracts/IDENTITY_V1.md). For package
profiles and their stable artifacts, read the
[Brand Kit package contract](../contracts/BRAND_KIT_PACKAGES_V1.md).

## Consumer integration

Consumer repositories keep human-reviewed intent in `.identity/` and use
Identity only through the CLI and generated package boundary:

```bash
identity v1-generate --repository-root "path/to/consumer"
identity v1-verify --repository-root "path/to/consumer"
```

Pin the release tag or full commit in consumer automation. Do not import
`Identity` Rust modules, point a consumer at `main`, or make generated output
canonical source. Empathy and OptiFlow provide the organization-level proof:
[Empathy #77](https://github.com/egohygiene/empathy/pull/77) and
[OptiFlow #46](https://github.com/egohygiene/optiflow/pull/46).

## Upgrade, rollback, and compatibility

Before upgrading:

1. Read [CHANGELOG.md](../../CHANGELOG.md) and the applicable contract
   migration notes.
2. Pin the new immutable Identity version in a reviewable change.
3. Run `v1-generate`, inspect the generated plan/manifest/checksums and any
   compatibility diagnostics, then run `v1-verify`.
4. Commit or publish the reviewed generated package as the consumer's process
   requires.

To roll back, restore the prior immutable Identity pin and the corresponding
generated package/manifest. Regenerate and verify from that version if the
consumer output is absent. Do not hand-edit generated files; doing so turns a
rollback into detectable drift.

The v1 source schema, package profile schemas, renderer view model, and CLI
commands are stable within their documented major versions. Additive optional
fields may arrive in a minor release; incompatible schema, package-profile, or
CLI changes require a new major and migration guidance.

## Release evidence and limitations

Every tag runs:

- locked dependency, format, lint, unit, contract, renderer, and browser checks;
- clean-room release builds and identical double-generation checks on Linux,
  macOS, and Windows;
- LF-normalized tracked text so source and visual-baseline SHA-256 evidence is
  stable across those platforms;
- a Linux x86_64 GNU archive with SHA-256 checksums;
- an SPDX SBOM and GitHub build-provenance attestation.

The static reference renderer and its browser tests are the public Brand Kit
smoke surface. Deployment of `https://egohygiene.io/identity` is owned by the
website repository and remains outside this CLI-release transaction. The
website must consume an immutable Identity release and perform its own
deployment and rollback checks before that route is announced.

See [SECURITY.md](../../SECURITY.md), [SUPPORT.md](../../SUPPORT.md), and the
[release process](RELEASE_PROCESS.md) for reporting, support, and maintainer
operations.
