# Brand Kit Quality Gates v1

## Status

Implemented by issue #12. The stable machine contract is
`identity.quality-report/v1` and the Rust entry point is `identity::quality`.

## Purpose

The quality layer decides whether a generated Brand Kit has enough evidence to
be released or published. It is intentionally downstream of source validation
and deterministic generation:

```text
reviewed .identity source
        ↓
resolve → generate → compiler manifest
        ↓
quality harness
        ↓
automated evidence + human review evidence + explicit skipped coverage
        ↓
package release / publication decision
```

A quality report never mutates canonical source, generated artifacts, approvals,
or a published surface.

## Authority model

Quality has two scopes:

- **package** — validates portable generated output. Renderer-only checks are
  recorded as skipped because no rendered interaction surface exists yet.
- **publication** — requires renderer interaction, high-contrast/no-color,
  target-size, focus, keyboard, copy/download, and performance evidence before
  `releaseAllowed` can be true.

A blocking check with `failed` or `review-required` makes
`releaseAllowed=false`. Warnings and explicit skips remain visible in coverage
but do not masquerade as successful validation.

## Stable status vocabulary

| Status | Meaning |
| --- | --- |
| `passed` | Required evidence exists and satisfies the current policy. |
| `warning` | Evidence is valid but deserves review or documents an unusual condition. |
| `failed` | A required rule is violated. Blocking failures prevent release/publication. |
| `skipped` | The check is not applicable in this scope or the owning surface does not exist yet. |
| `review-required` | Automation detected a decision boundary that requires explicit human evidence. |

Automated detection and human authority are separate fields. A visual diff may
be detected automatically while the accept/reject decision remains human.

## v1 automated checks

### Accessibility

- WCAG 2.2 AA contrast for the configured semantic text/background pairs;
- non-empty source alternative text;
- standard motion-duration budget;
- reduced-motion duration budget;
- generated raster dimensions and PWA maskable safe-zone evidence.

The default contrast contract validates `color.text` against `color.canvas` at
4.5:1. Additional semantic pairs can be supplied through `QualityPolicy`.

### Provenance and licensing

For every governed source role, the harness verifies:

- source bytes match the recorded SHA-256 digest;
- creator, method, source reference, and capture time are present;
- an approved SPDX license record is present;
- the asset approval identifier resolves to the Brand Kit's human-decision set;
- generated bytes and byte counts match the compiler manifest.

Missing license, origin, digest, or approval evidence fails closed.

### Visual integrity

- SVG parses through the pinned `usvg` boundary;
- scalable SVG sources declare a `viewBox`;
- SVGs contain no network or `file://` dependencies;
- extreme aspect ratios are surfaced rather than hidden;
- PNG dimensions match their versioned target profile;
- maskable targets carry verified compiler safe-zone evidence;
- visual targets are compared with an approved SHA-256 baseline.

A changed or missing visual baseline becomes `review-required` with both source
and generated context. Human approval may accept an intentional change without
teaching automation to approve creative decisions.

### Reproducibility and performance

- compiler-manifest digest and byte counts match actual generated files;
- each target respects its versioned `maximumBytes` budget;
- the default standard motion budget is 300 ms;
- the default reduced-motion budget is 0 ms;
- the reserved motion-asset budget is 1,000,000 bytes per asset;
- the publication renderer budget is 2,500 ms for initial boot evidence;
- the WCAG 2.2 AA target-size budget is 24 CSS px.

Motion-asset and renderer budgets remain visible even before those surfaces are
implemented. Issue #3 extends the same report rather than defining another
validator.

## Human review evidence

`HumanReviewEvidence` binds a decision to one stable check id:

- `checkId`
- `approved`
- `reviewer`
- `reviewedAt`
- `evidence`

Human review is required for small-size mark legibility and for visual baseline
changes. Publication scope additionally requires the renderer checks below.

## Renderer checks

Package scope records these as `skipped`; publication scope records them as
blocking `review-required` until #14 supplies automated/browser evidence:

- `renderer.keyboard-operation`
- `renderer.focus-states`
- `renderer.copy-download-controls`
- `renderer.no-color-high-contrast`
- `renderer.target-size`
- `renderer.performance-budget`

This is deliberate progressive coverage, not a claim that those checks pass
before a renderer exists.

## Visual baselines

The baseline registry uses `identity.visual-baselines/v1` with one approved
SHA-256 digest per target id plus source and generated context. Baselines are
review evidence, not canonical brand intent.

Checked-in adversarial fixtures cover:

- a normal scalable mark;
- an extreme aspect ratio;
- transparency;
- small-size review requirements;
- changed visual bytes;
- incorrect raster dimensions.

Future #3 fixtures add motion assets and landing-animation states to the same
registry/report semantics.

## Failure and recovery

| Failure | Recovery |
| --- | --- |
| Contrast below budget | Change semantic tokens, re-resolve, regenerate, and rerun quality. |
| Missing provenance/license | Correct the source governance record; never patch generated output. |
| Manifest drift | Discard drifted generated state and regenerate from canonical source. |
| Dimension/file-size failure | Fix the target adapter or intentionally version the profile budget. |
| Visual baseline diff | Compare source/generated context and record an explicit human decision. |
| Missing publication evidence | Run the owning renderer/browser suite and attach evidence. |

## Extension contract for issue #3

Visual-motion validation is an extension of this harness. It may add stable
quality checks, visual/motion fixtures, provenance fields, and policy budgets,
but it must preserve:

- `identity.quality-report/v1` status semantics;
- one release decision rather than a second validator;
- reduced-motion as a first-class requirement;
- explicit human approval for creative baseline changes;
- source-to-generated traceability;
- deterministic/offline checks inside the compiler-owned path.

If #3 requires a breaking report shape, the report schema must version instead
of silently changing v1.
