# Local initialization requests

These request files contain no invented project, license or approval facts.
They are draft-interface examples, not executed acceptance evidence. Use a
reviewed implementation containing #133; published `v1.0.0` has no `v1-init`.

From a disposable consumer, create the output's parent explicitly and supply
one request through `--request`. `empty.request.json` asks for an incomplete
starter; `existing.request.json` imports that consumer's existing validated v1
source without overwriting it. Select a new output directory every time.

The [initializer guide](../../docs/consumers/V1_INITIALIZATION.md) describes
facts, layers, explicit profiles, limitations and manual adoption. Do not copy
fictional example approvals into a real identity.
